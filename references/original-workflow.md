# 原版执行要点与制作步骤（存档）

> 原 SKILL.md 中这两节已在新 SKILL.md 的“硬约束”“制作流程”中改写；此处原文保留，便于核对没有遗漏规则。命令路径相对技能目录；原文中的 `$quote-poster` 调用方式改为在对话中触发。

## 执行要点

- 新制作默认先转简体，按完整句意补必要标点，确认实际文字与强调后再出图；文字转换不换字体。
- 常规制作只改配置，通过 `scripts/render-poster.cjs` 渲染；不复制、改写临时脚本，不用旧版入口绕过异常。
- 保持确认内容、默认字体、正文 −45 px 字距、1.55 倍强调、小字视觉行距及无越界碰撞；这些是不可自行放宽的约束。
- 在这些约束内，先保证语义断行和阅读节奏，再追求填满；无法兼顾时报告冲突及可选方案，改文字或强调仍需确认。
- 出图后程序验收必须通过，再实际看 PNG 并完成视觉检查。报告尚未看图时不视为交付通过。详见 [验收与异常处理](acceptance.md)。

## 制作步骤

1. 按选择规则确定版本，先按默认简体规则转换显示文字，再提取正文、来源、照片、明确要求的强调词，并理解文意拟定可建议的强调词。
2. 阅读 [统一参数](unified.md)，以自然语义编排 `lines`；短句优先三行或四行。原文字词及顺序必须保留；按下述断句规则补齐必要标点，不擅改词句。
3. 按“来源补全与出图前确认”核实署名，将实际正文断行、标点和完整来源先展示给用户，正文下方用大号标题单列放大词。先完成文字确认，再渲染；修改断行、标点或强调时也先确认新版文字。
4. 执行 `node scripts/render-poster.cjs config.json output-directory`，两个版本使用同一命令。未设置 `variant` 时脚本拒绝渲染，先完成用户选择。
5. 正式渲染器自动生成验收报告。程序通过后查看实际 PNG，按[验收清单](acceptance.md)检查视觉效果，再运行验收命令标记已看图；失败或尚未检查时不交付。
6. 按环境要求保存 PNG、HTML、排版 JSON 和验收 JSON，优先展示图片，再附可编辑 HTML。HTML 以 SVG 文字及 CSS 图层呈现，PNG 由 Canvas 使用相同坐标和字号输出，不声称 PNG 是 HTML 截图。
